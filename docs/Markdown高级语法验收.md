# Markdown 高级语法验收

第二阶段的目标是让脚注、公式、图表、提示块、高亮和目录在实际编辑、阅读和文件往返中保持一致。具体语法和限制见 [Markdown兼容性.md](Markdown兼容性.md)。

## 实现

- 文档先序列化为统一源码，再解析一次；依据同一份源码的行范围分配给各编辑块。正文、表格、提示块和文末脚注共用定义与编号。
- 分配解析结果时按源码行范围查找，避免每个编辑块重复扫描整篇文档；回归覆盖 1200 个连续列表项与段落的精确归属。
- 脚注支持命名、行内、嵌套和重复引用；每个引用有独立回链。定义前移不改变编号，循环引用不会无限递归，未引用的定义不生成多余脚注。
- 回链定位到具体引用，展开遮挡它的章节和提示块并设置键盘焦点。缺失定义显示原始标记和提示。
- KaTeX 渲染行内及块级公式；Mermaid 从本地分块加载。编辑后的旧图表不会继续充当新源码的结果。两者遇到错误均保留源码，修正后重新渲染。
- 提示块标题支持行内样式，正文支持嵌套内容；图片随提示块一起折叠。文内目录复用章节导航和重名标题规则，排除脚注正文中的标题。
- 文件导入、导出和备份保留这些语法；公式块统一为多行 `$$`。脚注中的图片与附件，包括未被引用的定义中的资源，也参与附件收纳；代码和公式内的字面链接不被改写。

## 固定回归样本

`tests/fixtures/markdown-advanced.ts` 包含混合高级语法。自动化检查覆盖：

| 层次 | 检查 |
| --- | --- |
| 语法和文档模型 | 全篇编号与逐处回链、任务项和提示块标题内引用、定义前移、循环及嵌套引用、表格行内脚注、转义与价格文字、目录和锚点一致 |
| React 渲染 | 行内和块级 MathML、错误源码、提示块语义结构和折叠状态、可访问的引用及回链名称、文内目录 |
| SQLite 和文件 | 三轮真实文件导入/导出、元数据备份恢复、脚注内图片附件复制、未引用资源保留 |
| Electron | 真实粘贴、预览和阅读、脚注点击/回跳、折叠章节展开、提示块图片折叠、公式与图表错误修正、保存重载、文件导出再导入、Mermaid 活动内容限制 |

## 本地验证

- `npm run build`：包含三个 TypeScript 配置的检查、生产构建和入口包体积检查。
- `npm run typecheck:system-plugin-examples`：独立的插件示例配置包含共享类型声明，检查通过。
- `npm test`：714 个用例通过，无跳过。Windows 进程身份测试需要能查询本机进程列表的运行权限。
- `npm run test:markdown-spec`：1329 条官方样本全部完成三轮往返；原有产品差异不变，无新增失败，详见 [规范验证报告](Markdown规范验证报告.md)。
- 完整 Electron 回归：104 个用例通过，覆盖编辑器、Markdown、长文档、链接、插件与重启持久化。
- 最终解析范围优化后重新构建，高级语法与长文档的 5 个 Electron 用例再次通过。
- 保持入口 JavaScript 450 KiB、CSS 96 KiB 的原有构建限制；图表和高级样式按需加载，未放宽包体积预算。

完整 Electron 检查命令：

```text
npx playwright test --grep '@electron'
```

CI 对提交版本执行 Linux 类型检查、全量单元/集成测试、规范样例、构建和 Electron 验收，以及 Windows 打包运行时验收。应以对应提交的工作流结果为准。

本阶段补齐高级内容能力。后续的表格编辑、复杂任务交互和格式操作见 [编辑体验验收](Markdown编辑体验验收.md)；文件互通、链接更新、性能和竞品对照继续按 [提升计划](Markdown提升计划.md) 的第四、第五阶段推进，当前不能据此宣称整体优于竞品。
