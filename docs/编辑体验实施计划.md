目标：按与 Notion 对照后的优先级完善编辑体验；每阶段完成验证后提交、推送，并核实该提交的 GitHub CI 全部通过。基线为 `0bcc33e`，对应 CI #291 全部成功。

## 阶段与验收

1. **正文富文本与连续编辑**：默认所见即所得；跨块局部文字选择、格式、替换与删除；连续光标、分段合并；中文组合输入；撤销重做恢复选区。继续以 Markdown 和稳定块 ID 保存，保留标签、树关系和高级语法；源码编辑模式保持可用。新模式与源码模式分别提供真实交互测试。
2. **富文本剪贴板**：网页/Word/Notion HTML 保留标题、格式、链接、列表、表格；截图与附件保持可用；代码等源码输入保持字面内容；粘贴不继承外来块身份。
3. **正文媒体操作**：直接调整尺寸、裁剪、对齐、独立图注与替代文字；保存、历史、Markdown 导入导出及备份往返；保持原附件文件。
4. **统一块菜单与格式入口**：单块及多块转换一致；复制块链接、跨文档移动；下划线、文字颜色、可选文字背景色；键盘及选区恢复。
5. **可视化结构编辑**：提示块类型/标题/图标；Toggle 创建、转换与容器编辑；普通表格列宽、行列拖排与快捷操作；保留源码往返。
6. **页面编排**：可调整宽度的分栏、文内数据库视图、可在多处编辑的同步块；跨页面更新、引用身份、导入导出与历史恢复。
7. **性能验收**：大文档输入、选区、挂载与保存测量；完整单元/集成/Electron E2E 回归；所有最新 GitHub CI 作业成功。
8. **后置协作编辑**：段落评论、建议编辑与多人协同；结合现有同步机制设计身份、冲突处理及协作状态，不以单机模拟证明多人协同已完成。

阶段 1、2 共享编辑器与选区模型，可以一起验收为首个提交阶段。每次提交前至少运行 `npm run typecheck`、`npm run test`，编辑交互变更另跑相关后台 Electron E2E、构建和 Markdown 标准往返检查；最终 CI 覆盖 Linux 三个 E2E 分片与 Windows 验收。不得降低既有标准/性能门槛、屏蔽失败或移除后台窗口限制。

### 块菜单与格式阶段

两种编辑模式共用单块／多块动作，支持完整类型转换、复制稳定块链接、复制／删除子树和选择目标文档移动。仅显式选中的块改变类型，折叠子块保留自身类型；移动携带完整连续同级子树，保留块 ID、完成状态、标签、列表格式及原创建时间。移动、成对撤销／重做、引用重写与两侧历史在同一事务中提交。重启后仅当所有参与文档的内容与路径仍一致时恢复该移动的撤销入口，后续编辑不会被覆盖。

块链接使用 Markdown 路径与 `#^块ID`；旧路径可定位到移动后的归属文档；文档或祖先改名、移动时，在路径事务中保存旧路由，并验证重启后仍可达。同步接收端也在远端路径改写前保存实际见过的路径与原块 ID，排除刚移入的块，避免虚构旧目标路径。明确缺失的块不会错误回退到同名标题。目标文档加载、菜单按需加载及异步回复均核验当前会话，离开窗口或转移注意力后不会自动夺回焦点。源码及富文本均支持下划线和九种有限文字／背景色，颜色可独立清除，中文组合输入与反向选区保持原有行为。

WebDAV 接收会在发布清单前核验批次整体归属，再在数据库事务中重复核验；移动身份先改归属，再处理来源释放／删除，避免接收顺序造成主键冲突或丢块。来源或目标出现冲突时阻止部分移动，保存可重启恢复的冲突报告，选择远端或独立副本后可重试。拟发布清单也整体核验块归属；移动双方均有冲突而只处理一方时，拒绝发布重复身份或丢块的清单，知识、同步基线与最后同步时间保持不变，完整处理双方后仍可重试。

适用限制：移动选择须为连续同级完整子树；命名脚注需要追加定义时，必须存在可可靠定位的顶层段落宿主，否则在写入前拒绝。同步协议 v1 保留接收设备曾观察到的旧路径，尚不传输完整历史别名及成对撤销日志；普通 Markdown 和当前备份也不携带移动日志与全部历史路由，正文链接按移动时重写后的新路径往返。文字颜色以有限 `data-knowbook-text-color`／`data-knowbook-background-color` 属性保存，KnowBook 两种编辑模式及阅读保持颜色；第三方 Markdown 阅读器未加载相应样式时可能仅显示内容和下划线。
