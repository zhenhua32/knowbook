# KnowBook 使用文档

## 产品说明

KnowBook 是本地优先的知识管理桌面应用。SQLite 是唯一事实源，Markdown 用于备份、恢复和单文档导出。

主要功能：

- 文档树和块编辑器
- 页面链接、块引用、出链和反向链接
- 统一 Database 工作台（Table / Board / Cards）
- AI 问答、选区编辑、自动摘要和相关笔记检索
- Markdown 快照备份与恢复
- 网页剪藏和浏览器扩展桥接
- 隔离的 v2 动态插件与 Full Trust v3 系统插件

相关笔记检索当前基于标题、摘要和块正文做本地关键词匹配，不使用 Embedding 或向量数据库。

## 安装、启动与构建

开发模式：

```bash
npm install
npm run dev
```

生产构建：

```bash
npm run build
```

构建产物写入 `out/`。本地打包：

```bash
npm run dist
```

安装包和解包目录写入 `release/`。一次性执行打包和本机产物检查：

```bash
npm run release:verify-local
```

## 首次使用

1. 在侧栏选择界面语言。
2. 创建或打开一篇文档。
3. 在配置中心检查实际数据库和备份路径。
4. 如需 AI，填写 Base URL、Model 和 API Key，再启用 AI。
5. 手动执行一次备份，并确认备份目录中生成了 Markdown 文件。

开发模式和未打包应用不支持自动更新，这是正常状态。

## 界面导航

侧栏包含：

- 文档：文档树、编辑器、关系和网页剪藏。
- 总览：工作区统计、最近文档、事件和插件卡片。
- Database：在统一工作台中浏览全部文档和自定义数据库。
- AI 助手：AI 配置状态、问答和相关笔记。
- 插件中心：动态插件与系统插件的状态、安装、启停、诊断和恢复。
- 配置中心：语言、更新、备份和浏览器桥接。

常用全局快捷键：

- `Ctrl/Cmd + 1…6`：切换主要页面。
- `Ctrl/Cmd + K`：打开或关闭全局搜索。
- `Ctrl/Cmd + F`：在文档页打开或关闭块搜索。
- `Alt + ArrowLeft / ArrowRight`：文档导航后退或前进。
- `Escape`：关闭搜索或清除当前块选区。
- Database 页内 `/`：聚焦记录搜索。
- Database 页内 `Ctrl/Cmd + Shift + L`：聚焦数据库选择器。
- Database 页内 `Ctrl/Cmd + Shift + V`：聚焦新建视图。

## 文档与块编辑器

### 文档树

- 使用文档树上方的新建按钮创建根文档。
- 使用文档菜单创建子文档、移动或删除文档。
- 同一父级下标题必须唯一；冲突时应用会拒绝移动，或在保存标题时生成唯一名称。
- 删除文档会删除当前文档，并把直接子文档提升到被删除文档的父级。
- 进入其他文档前，应用会尝试保存当前草稿；树结构校验失败时会阻止跳转。

### 块类型

当前包括：

- 一级、二级和三级标题
- 段落
- Todo
- 引用
- 无序列表
- 有序列表
- 代码块
- 数学公式
- 分割线

输入 `/` 可打开块命令。支持常见快捷前缀，例如 `#`、`##`、`>`、`-`、`1.`、`- [ ]`、`- [x]`、`$$`、`---` 和三反引号。

### 块操作

- `Enter`：续写标题、列表或待办。
- `Ctrl/Cmd + Enter`：在当前块下方插入新块。
- `Alt + Enter`：在光标处分裂块。
- `Tab / Shift + Tab`：调整可嵌套块的层级。
- `Alt + ArrowUp / ArrowDown`：移动当前块或连续块选区。
- `Ctrl/Cmd + Shift + D`：复制当前块或选区。
- `Delete / Backspace`：删除块选区；在块首使用 Backspace 可降级部分块格式。
- 拖拽块时左右移动，可预览新的父级和深度。
- 多行粘贴会拆为多个块；存在连续块选区时可整体替换。

撤销历史对连续输入采用短暂防抖；执行撤销时会先提交尚未入栈的快照，因此刚输入后也可以立即撤销和重做。

中文输入法选词期间，回车、方向键、退格和 Tab 交给输入法处理；候选文字不会触发块快捷操作或写入自动保存与撤销历史，确认输入后恢复。

文档标题旁显示“待保存／保存中／已保存／保存失败”。失败时草稿仍在，点击保存可重试，继续编辑也会重新尝试自动保存。工具栏和侧栏菜单的“复制 Markdown”“导出 Markdown”均包含当前打开文档的最新草稿与标题，无需等待自动保存完成。

### 长文档阅读与导航

文档顶部的导航栏在滚动时保持可用，显示当前章节和滚动进度。点击“大纲”可以筛选一级、二级标题并跳转，跳转不会直接进入编辑状态。

点击“阅读”可查看当前草稿的排版效果，正文编辑控件会隐藏；点击“编辑”返回修改，尽量保留正在阅读的内容块与相对位置。阅读视图中的待办状态仅供查看。

阅读位置按文档在本机记忆，支持切换文档、历史返回和重启后重新打开文档。定位使用内容块 ID，前文增删后仍尽量回到原来的段落；原块被删除时退回邻近的滚动位置。最多保留最近 100 篇文档的位置，目录、搜索和引用跳转优先于记忆位置。

标题左侧和大纲中的小箭头可以折叠章节，一级标题包含下面的二级标题，二级标题包含直到下一个同级或更高层级标题之间的内容。大纲提供“全部折叠”和“全部展开”。折叠不会删改正文，也不会影响全文导出；折叠状态按文档在本机记忆，最多保留 100 篇，重启后仍可恢复。

在大纲中点击章节旁的“只看”，或点击“只看本章”，可专注阅读、编辑一个章节。顶部“显示全文”返回整篇文档。专注状态也会记忆；本章模式下，在段落中连按两次 `Ctrl/Cmd + A` 选中本章所有块，底部“新增块”在本章末尾创建普通段落。收起正在编辑的章节时光标移至可见标题，保持编辑上下文不变后展开会恢复先前的光标或选区。

点击“查找”或按 `Ctrl/Cmd + F` 打开文内搜索。输入关键词后按 `Enter` 定位第一个结果，再次按 `Enter` 跳到下一个；`Shift + Enter` 返回上一个，`Esc` 关闭。搜索始终覆盖全文，定位会展开目标所在的折叠章节与列表，结果摘要显示命中附近的文字。专注本章时，目录、搜索和引用跳到其他章节会自动切换到目标章节。

### Markdown 与引用

支持 H1–H6、嵌套列表、任务列表、引用、代码、GFM 表格及常用行内样式。粘贴、阅读、复制与导出使用统一语法，详细规则见 [Markdown 兼容性](Markdown兼容性.md)。

- `[[文档名]]`：仅当标题在工作区唯一时解析。
- `[[路径]]`：按完整文档路径解析。
- `[[块ID]]`：引用当前文档中的块。
- `[[路径#块ID]]`：引用另一文档中的块。
- 按住 `Ctrl/Cmd` 点击引用可跳转。

页面级 `[[文档名]]` 和 `[[路径]]` 会进入出链/反向链接索引。跨文档块引用目前可预览和跳转，但不会作为页面链接写入出链/反向链接索引。

### 单文档导出

文档菜单支持复制或保存 Markdown。当前打开文档导出最新草稿与标题，包括折叠或专注模式隐藏的内容；其他文档导出已保存的内容。

## 网页剪藏

### 应用内 URL 剪藏

1. 在文档树中选中父文档。
2. 展开文档辅助区。
3. 在网页剪藏输入框粘贴 `http` 或 `https` URL。
4. 执行剪藏。

应用会提取正文、常见元数据和图片，并把图片保存到 userData 下的资源目录。相同来源 URL 与内容哈希已经存在时，会复用现有文档。

默认阻止访问本机和私有网络目标。只有显式设置开发环境变量 `KNOWBOOK_ALLOW_PRIVATE_WEB_CLIP=1` 才会放开此限制。

### 浏览器扩展桥接

1. 在配置中心启用浏览器桥接。
2. 复制扩展提交地址和授权令牌。
3. 在 Chromium / Edge 中加载仓库的 `web-clip-extension/`。
4. 把提交地址和 Bearer token 填入扩展。
5. 在目标页面执行剪藏。

桥接服务只监听 `127.0.0.1`，默认端口是 `3210`。修改端口或重置令牌后，需要同步更新扩展配置。授权令牌等同本机写入凭据，不要公开分享。

扩展的详细说明见 [web-clip-extension/README.md](../web-clip-extension/README.md)。

## Database

Database 页面是一套统一工作台，不再要求先选择“文档目录”或“独立数据库”模式。页头的数据库选择器固定包含“全部文档（系统）”，并列出所有自定义数据库；切换来源后，视图标签、工具栏和数据画布保持在相同位置。

页面从上到下分为：数据库页头、保存视图标签、视图工具栏和单一数据画布。工具栏可调整搜索、组合筛选、多字段排序、分组、字段显隐和 Table / Board / Cards 布局。变更后点击“保存更改”会写回当前视图，也可以另存为新视图。

### 全部文档

“全部文档”以工作区文档为记录，标题点击后进入文档编辑器。支持以下自定义字段：

- Text
- Select
- Multi-select
- Date
- Checkbox

Table 视图用于直接编辑字段。Board 可按父级、Select、Multi-select、Checkbox、Date 或 Text 分组；拖动卡片会更新对应字段值。系统字段可在字段抽屉中隐藏，但标题不能隐藏或删除。

### 自定义数据库与记录

自定义数据库拥有自己的字段、记录和保存视图。每条记录都有必填标题，可选关联一篇文档。点击记录标题打开详情抽屉；如已关联文档，可从抽屉跳转到文档。支持：

- Cards / Table / Board
- 文档关联
- 多条件字段筛选和多字段排序
- 按字段分组
- 保存字段显隐、顺序、列宽、卡片摘要字段和布局
- 批量字段应用、清空、解绑和删除
- 数据库、字段、视图和记录的应用内删除确认

点击“字段”打开字段管理抽屉，可新增、重命名、维护选项、显隐、调整当前视图顺序或删除字段。字段删除会同时删除已有值，建议先执行 Markdown 备份。

## AI

### 配置

在配置中心填写：

- Base URL：OpenAI-compatible API 根地址，例如 `https://api.openai.com/v1`。
- Model：服务端可用的模型名。
- API Key：保存在本地 SQLite 设置中。
- Enabled：总开关。
- Related notes：允许问答使用本地关键词相关笔记。
- Auto summary：文档保存后自动生成摘要。

Base URL 应填写 API 根地址，不要填写完整的 `/chat/completions` 地址；应用会自动追加该路径。

### 功能

- 文档问答：把当前文档和可选的相关笔记发送给配置的模型。
- 选区编辑：摘要、改写、转 Markdown 表格或自定义指令；先预览，再决定是否替换。
- 自动摘要：内容达到最低长度且摘要仍为默认值时触发。
- 手动自动化：只运行当前已启用的自动化。

AI 请求会把相应笔记内容发送到你配置的 API 服务。处理敏感内容前，请确认服务端的数据政策。

## 备份、恢复与数据位置

### 数据位置

默认路径基于 Electron `app.getPath('userData')`：

```text
<userData>/
  storage/
    knowbook.db
    knowbook.db-wal       # 运行时可能存在
    knowbook.db-shm       # 运行时可能存在
    assets/
    plugin-revisions-v2/
  backups/
    markdown/
    system-plugins/
  system-plugins/
    artifacts/
    runtime/
    data/
    logs/
```

“总览”会显示当前实例实际使用的数据库和备份路径。测试或开发环境可以通过 `KNOWBOOK_USER_DATA_DIR` 覆盖 userData。

### Markdown 备份

- 应用启动后会立即执行一次备份，之后按固定间隔备份。
- 正常退出时会尝试再执行一次备份。
- 配置中心可手动触发。
- 每次备份会用新的完整快照替换旧快照。
- 文档 frontmatter 保存文档 ID、路径、摘要、结构化字段和块元数据。
- 独立 Database 写在备份目录的 `__knowbook/databases/` 下。

### 恢复与普通 Markdown 导入

应用会先判断所选目录是否包含标准位置的 KnowBook 清单 `__knowbook/databases/index.md`：

- 完整 KnowBook 快照：创建或更新快照中的文档，并删除快照范围内已不存在的文档；独立 Database 同样按清单同步。
- 普通或旧版 Markdown 目录：只创建或更新识别出的文档，不删除现有文档或独立 Database。

完整快照恢复仍可能删除工作区内容。执行前务必：

1. 关闭其他 KnowBook 实例。
2. 复制整个 `storage/` 目录，至少保留数据库及可能存在的 WAL/SHM 文件。
3. 确认所选完整快照目录由 KnowBook 生成。
4. 先在测试数据目录验证重要备份。

### 重置本地数据

不要使用文档中写死的用户名路径。需要重置时：

1. 在“总览”确认实际数据库路径。
2. 完全退出应用。
3. 把对应 userData 目录重命名为一个备份目录。
4. 重新启动应用，确认新工作区正常后再决定是否删除旧目录。

## 插件管理

插件中心管理两个独立通道：

- **Plugin Platform v2**：AI 创建的动态插件与已安装市场包。检查器显示 capability 权限、最近 revision 和运行日志，并提供启停、隔离恢复、卸载与 AI 定制入口。
- **System Plugin v3**：从目录或 ZIP 准备安装，核对插件 ID、版本、内容哈希和依赖计划，由用户确认完整本机访问风险。安装、启用和回滚后按状态提示重启；插件中心提供 Main/Renderer/后台服务状态、数据与日志目录、安全模式和恢复操作。

应用内置的 v3 **主题切换** 无需单独安装，首次启动自动启用。在配置中心可选择云白、暖纸、青苔、海湾、午夜、紫夜，或跟随 KnowBook 原有外观。插件中心标注“来源：内置”，支持停用和重新启用；版本随应用更新，保留之前的主题选择和停用状态。

旧 v1 插件系统已移除。仓库和 userData 下的旧 `plugins/` 目录不再自动扫描，也没有旧版重扫、重载或安装入口。旧源码和历史数据保留，自定义插件需改写成 v3 后重新安装；不能仅修改 manifest 就假定旧 SDK 可用。

AI 页面同时提供 Plugin Platform v2 工作台。你可以直接描述想要的 KnowBook 改动；助手会先检查平台能力，生成并验证不可变插件 revision，展示插件 id、revision id、变更和权限差异，然后把精确 revision 激活到当前工作区。后续对话可以继续检查、修改、停止或回滚同一个插件。

## 插件开发

### Plugin Platform v2

动态 v2 插件只允许导入应用提供的精确版本 `@knowbook/std/*` 模块，当前基础模块为 `@knowbook/std/plugin@1.0.0`。运行时不提供 Node.js、Electron、文件系统、网络、shell、定时器或 `npm install`；文档读写、插件状态和 UI 通知必须通过 manifest 声明、绑定精确 revision 并由 host broker 校验的 capability 完成。

AI 生成插件从创建起就是 workspace 安装；应用重启时会恢复仍处于启用状态且授权有效的安装，但不会静默重放未完成的助手工具。仓库内置的 `activity-pulse-v2` 演示了 Dashboard 卡片、文档动作、工作区事件订阅和异步 capability 调用。

### System Plugin v3

v3 包声明 `schemaVersion: 3`、`trust: "full"`、`fullAccess: true`，并明确指定 `entries.main/renderer/service` 至少一个入口。它可以使用完整 Node/Electron、任意 npm 依赖和宿主 React；风险声明用于确认和审计，不是隔离权限。

- [Activity Pulse](../plugins/activity-pulse/README.md)：从旧插件迁移的 v3 实例，保留最新文档活动卡片、从首个非空块生成摘要和持久化摘要前缀。
- [主题切换](../plugins/theme-switcher/README.md)：随应用内置并默认启用的六款浅色 / 深色预设，在配置中心点击应用、自动保存；可跟随应用外观，停用后恢复原样。
- [v3 Starter](../examples/system-plugin-v3-starter/README.md)：展示 Main、Renderer 和后台服务。
- [v3 开发指南](system-plugin-v3-development.md)：类型入口、生命周期、依赖构建、状态迁移、资源清理与故障恢复。

外部插件在插件中心选择工程目录，确认精确安装内容后重启。源码修改后重新准备并确认安装；内置主题插件则随应用重新构建和更新，不要编辑宿主发布的 artifact。旧 v1 的 `activate(api)`、`contributeDashboardCard` 和 `contributeSetting` 接口已删除，需要改用 v3 Main 服务与 Renderer 插槽，不能由兼容层执行。

## 常见问题

### AI 按钮不可用

确认 AI 已启用、Base URL 和 Model 非空、API Key 已保存，并且服务端支持 OpenAI-compatible `/chat/completions`。

### 开发模式显示“不支持自动更新”

自动更新仅在正式打包版本中启用。

### 插件未出现

外部 v3 插件需要先在插件中心选择目录或 ZIP、确认安装并按提示重启；仅把文件放进 `plugins/` 目录不会加载。内置主题插件若未显示，请检查是否停用或进入了安全模式。检查 manifest 和声明入口、版本兼容性及依赖日志。v2 插件则检查是否已激活对应 revision、是否停用或被隔离，并查看运行诊断。

### 原生 SQLite 模块加载失败

执行：

```bash
npm run postinstall
```

这会为当前 Electron 版本重建 `better-sqlite3`。
