## 最小状态与版本边界

建议升为 schema 27，保留 schema 26 全部现有表、关键触发器和稳定路由定义，另加四张真实状态表。

- `synced_group_lifecycle`：每个真实组一行，绑定 groupId／creationId。状态为 `active` 或 `retired-create`；保存状态版本、本次 create journal 身份、最近 activation 的 revision／topologyRevision／准确语义哈希／使用者集合。保留稳定 group 行，因此历史与 pin 的 RESTRICT 外键继续有效。
- `synced_group_retirements`：退役状态的完整冻结 GroupWire JSON、准确哈希、create journal 外键与退役时刻。退休组不得有 canonical 物理块、实例登记或存活 canonical ledger。
- `synced_exposure_attempts`：每次真实对外发布的 attemptId、规范请求哈希、渠道、目标指纹、精确 publicationHash、`possible`／`confirmed` 状态及时间。不存凭据。
- `synced_group_exposure_members`：本次发布准确参与的 group／creationId、CAS 与语义哈希。全部 RESTRICT 外键，发布后不能删除记录或更换成员来重新获得“未发布”资格。

组的曝光状态为 `never`／`possible`／`confirmed`／`unknown`。迁入的旧 26 组一律为 active／unknown；不依据缺少同步基线、当前零实例或配置已被删除推断 never。只有同一结构事务新建、尚无生命周期行并有真实 create journal 证明的组才可注册 never；已有 unknown 永不通过此入口升级为 never。

## 迁移与旧读取器保护

启动先按原版本严格验证 schema 26 权威；现有安全副本成功后，在一笔外层事务内新增状态结构、回填旧组并检查约束，最后才推进 user_version 27。失败整笔回滚；不修补损坏的 26 权威，也不为损坏的 27 库重建状态。数据库恢复同样先只读验证原版本、生命周期结构与能力门禁，再安装。

27 的状态缺失、非法状态定义或关键触发器损坏必须拒绝。正常读取只对所请求的真实组检查完整状态；retired-create 返回 missing，选择器、wire 与公开导出只包含 active。最后实例删除形成的 active orphan 仍是 live group，不能与 retired-create 混淆。当前构建尚无完整 canonical 导出，已有能力门禁继续保留，不能仅因此迁移上线就对用户开放同步块。

旧 schema 26 Store／恢复器必须凭 user_version 拒绝 27，包括全部组已退役的库。用已经归档的真实 `6d61134` 完整源码运行旧读取器，验证拒绝前后数据库字节、schema、路由及 WAL／SHM 保持不变；不能用当前实现模拟旧读取器。此迁移是单向边界，27 库不能再由旧版本打开；迁移前副本保留为回退依据。

## 创建撤销与发布竞态

create Undo 只消费所有参与宿主精确尾和 after side，并核最近 activation 的准确内容、owner、使用者与 pin 依赖。必须为 never 且无任何可能曝光记录。删除自身 registry／实例与 canonical 物理行后，原 selected child 显式转回原 document；ID、createdAt 和旧路由均保留。辅助闭包 child 保留为 group 的 retained 身份。完整 W、退役定义、fresh token／各宿主 cursor 与准确 ACK 同事务提交。

Redo 核 host before side、create journal 与退役定义准确哈希，再核所有原 ID 的真实归属、保留资格及原创建时间。从冻结定义重建原 group／child／instance 身份，只更新本机 CAS 和实例 bindingVersion。每次重新激活保存新的准确 activation guard。发生内容修改、新使用者、仍有外部历史／回收站／模板 pin、身份冲突或最终投影非法时拒绝，保留 token／Redo，零写入。不能分配替代 child ID 或造空 placeholder 来伪称撤销成功。

发布前先在独占 IMMEDIATE 事务重验真实 active 组和精确发布内容，durable 写入 possible，提交后才能发 HTTP 或产生可恢复为同 incarnation 的 V3 对外文件；网络等待不持 SQLite 事务。发布 claim 先提交则 Undo 拒绝；Undo 先提交则旧发布计划失效。成功可记 confirmed，但超时、丢 ACK、崩溃、412 重试或删除配置都不能清除 possible。私有正常关闭草稿日志不算发布。现合同首版没有出站组删除协议，因此 possible／confirmed／unknown 的 create Undo 必须拒绝归还 owner；本机零实例不能证明远端安全。

protocol 5 与 V3 的 portable GroupWire 不加入本机生命周期、CAS 或 executable history；本方案不扩展多人／多机验收。
