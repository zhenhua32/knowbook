## 下一片设计边界：原 ACK mailbox（尚无代码）

最后只分派了 ignored candidate 准备，代理因额度限制结束；实际检查没有 `stage6c-source-commit-mailbox-candidate/`。以下是 Root 的设计决定，**不是已实现功能**：

- 给原 working receipt 一个独立的只读 committed 查询口，mint 时私有登记原 Endpoint／FrameVersion；查询不调用 live／scope／getCurrent，也不给旧端点新写权限。
- acknowledge 在全部既有身份／内容校验后、publish 前，为实际 pending 捕获的原 version 记录一次 immutable ACK；即使 working 已 expired／disposed，也不能丢失这份已提交事实。只读诊断不代表恢复后可采用该来源。
- 保留 submitted sequence 与各 accepted view sequence 的区别；F1／F2、净抵消视图和迟到 ACK 不按同文重配。
- Source accepted checkpoint 即使在 dispose 后首次读，也能取得属于自己的原 ACK；原 accepted result memo 不变。
- 基线、伪造 handle、未知／未提交退休版本、invalid ACK 均不能产生 committed receipt。lost ACK 只在真实 operation 查询结果通过现有 controller 校验后变为 known，不把 transactionId 当作 clientOperationId。
- 测试涵盖 ACK 后 dispose 晚读、ACK publish 回调重入 dispose、ACK 前 dispose、丢失 ACK、scope 回调抛错但只读口无 callout、prefix／净抵消及 Source 晚读。使用真实 registered controller；mock 合同端口覆盖不能改称 Main／SQLite 验收。

更后的 owner／history-ticket 设计见快照内 `stage6c-source-history-handoff-design/proposal.md`。保守取舍：dirty W 等自己的原 ACK，baseline 必须完整精确握手，不匹配明确重开；未 ACK birth 的原始 Undo 可保留，但持久 Apply 可能等待来源；只有 validated mailbox 的原 operation ID 驱动 lookup。现 Main 结果没有独立 read-owner epoch，拟以原 connection／recovery 绑定的 baseline ticket 作 lease 尚待独立审查，不是当前能力。
