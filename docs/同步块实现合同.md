## 存储、类型与事务
### 1. 固定不变量与存储

- schema26／WebDAV protocol5／完整备份 V3；canonical 当前正文独立存一份，宿主仅存叶占位 `type:'synced-block'`、`id=instanceId`、严格 content `{version:1,groupId}`。
- canonical 非空且禁止任何 nested sync；最后删除由前端一次明确编辑换成 fresh ID 的真实空 paragraph，后端拒绝空 forest，不自动造 filler。
- canonical relative depth 从 0 起；每处透明展开 `instance.depth + child.depth <= 6`。全部当前实例、所有入口、事务最终图统一验证，不能 clamp／flatten。
- `blocks` 保持 document-only；新增 `synced_groups`、`synced_group_blocks`、`synced_instances`、operation／history journal。全局 `block_identities`＋双表排他约束统一 ordinary／instance／canonical child 的身份占用。
- routes FK 先迁稳定 identity；物理转域只改变 live owner，不删除 identity 后重插，不丢旧 routes。retained 身份保留，resolver 只返回 live owner；普通同宿主 Undo 仍可合法恢复原 ID，跨域认领必须由原子规划授权。
- host/canonical/owner/instance/origin/bindings/索引/journal 一事务；最后 live instance 删除不删组，保 trash/history/journal/template 的持久 pin。

### 2. 必要公共类型（实际导出使用 Synced 前缀，严格有限 runtime shape）

```ts
type Uuid = string
type BlockId = string // typeof string && trim 非空；保存原字节，允许历史空白／中文／冒号
type StableBlockDraft = Omit<DocumentBlockDraft, 'id' | 'parentBlockId'> & { id: BlockId; parentBlockId: BlockId | null }
type CanonicalEdit = StableBlockDraft // 不接收 sortOrder／createdAt／updatedAt；拒绝 synced-block
type CanonicalWire = CanonicalEdit & { createdAt: string }
type SyncedOriginV1 = {
  version: 1; documentId: string; pathAtCreation: string; firstInstanceId: Uuid } // 全immutable，无linkContextPath
type LinkTarget =
  | { kind: 'document'; id: string; state: 'live' | 'missing' }
  | { kind: 'block'; id: BlockId; documentId: string | null; state: 'live' | 'missing' }
  | { kind: 'heading'; documentId: string; slug: string; state: 'live' | 'missing' }
  | { kind: 'unresolved-url'; path: string; fragment: string | null }
type LinkBinding = {
  blockId: BlockId; from: number; to: number; raw: string
  syntax: 'markdown' | 'wiki'; target: LinkTarget
}
type BindingKey = Omit<LinkBinding, 'target'>
type BindingClaim =
  | { kind:'continue'; source:BindingKey; destination:BindingKey }
  | { kind:'copy'; source:{kind:'current';key:BindingKey}|{kind:'ticket';ticketId:Uuid;entryId:Uuid}; destination:BindingKey }
  | { kind:'new'; destination:BindingKey }
type InstanceGuard = { instanceId: Uuid; hostDocumentId: string; bindingVersion: Uuid }
type GroupGuard = { groupId: Uuid; expectedRevision: Uuid; expectedTopologyRevision: Uuid }
type HistoryState = { cursor: Uuid; undoToken: Uuid | null; redoToken: Uuid | null }
type GroupSnapshot = {
  groupId: Uuid; creationId: Uuid; createdAt: string; revision: Uuid; topologyRevision: Uuid
  origin: SyncedOriginV1; bindings: LinkBinding[]; blocks: CanonicalWire[]
  instances: Array<InstanceGuard & { depth: number; parentBlockId: BlockId | null; parentType: string | null }>
  history: HistoryState; maxRelativeDepth: number
}
type HostWorkingBefore = {
  documentId: string; expectedPersistedUpdatedAt: string
  workingBefore: { title: string; summary: string; blocks: StableBlockDraft[] }
}
type Failure =
  | { status: 'conflict'; kind: 'group' | 'topology' | 'host' | 'history'; groups: GroupSnapshot[]; hosts: DocumentDetail[] }
  | { status: 'missing'; kind: 'group' | 'instance' | 'document'; id: string }
  | { status: 'invalid'; code: 'forest' | 'nested-sync' | 'identity' | 'binding' | 'depth' | 'budget'; blockingInstances: InstanceGuard[] }
  | { status: 'idempotency-mismatch' }
```

新 group／instance 用 UUID；旧 child ID 原字节兼容，不加长度／字符集／`id===id.trim()` 门槛。CanonicalWire 的 createdAt 必填且有效、原字节保留；新 child 首次接受由后端定时，迁入旧 child 保原 created_at。接收选定 wire 时采用其 createdAt，即使本机旧普通行同 ID 的时间不同；updatedAt 仅本机记录、不入 wire/hash。V3 保原 createdAt，生成新本机 CAS。

Origin 逻辑 documentId／firstInstanceId 删除后仍保留，nullable 展示 FK 不可反推它们。旧链接靠 typed bindings 稳定 ID 维护，未来相对链接只按 immutable pathAtCreation；bindings 范围必须与当前正文解析吻合，不能信客户端伪造。V3 对 missing origin／targets 也 reservation，避免恢复误绑碰巧同 ID 的本机对象。

绑定的 target ID 是稳定语义；其 state／documentId hint 也是已捕获 side 与回执的一部分，历史恢复不得依据今日路径替换 ID 或改写旧 side。当前存在性与块 owner 必须另查实际 ledger／物理归属；V3 的 missing 闭包也以真实图为准，不能把历史 hint 当作存活权威。同次新 canonical child 的 self／cross 引用依据已通过身份授权的完整候选集合解析，不提前制造 ledger 行。

`[self]()`、`[self](<>)` 及实际生效的空引用定义允许 `from === to`／`raw === ''`，只用于 Markdown 的真实空目的地解析点，目标仍按 immutable Origin 捕获。通用范围校验拒绝重复点位、Wiki 零宽及重叠范围；Main 完整 AST 覆盖核验拒绝任意空子串、代码／图片中的伪绑定和遗漏。附件改写必须精确平移该点；标题、空白及未修改源码保留。

内容提交核对真实 instance＋hostDocumentId＋bindingVersion、content/topology CAS、身份及全部实例最终深度。跨文档 move 后旧宿主即使 instanceId 仍存在也不能写。内容成功不 touch host.updatedAt、不 reset host dirty。每次有语义变化才 mint 本机 UUID CAS；binding 只因换组／owner／parent／depth／重建而变，普通前方插字造成 sort_order 平移不变 token、不进结构 API。

实例位置的 parentType 是 Main 从真实宿主父块派生的只读快照字段；根实例为 null，不增加持久化字段、输入授权或 portable wire 字段。引用透明参与角色校验：宿主列表可拥有根全部为列表项的共享正文；普通段落不能借引用进入列表。宿主叶引用先延期这一角色判断，完整候选图按实际 canonical 根校验，列布局仍只能直接拥有真实 column。父类型变化影响引用约束时通过结构事务重新校验并推进组 topology CAS；前端也据此在接受富文本候选前拒绝已知非法角色。

clientOperationId＋requestHash 唯一幂等；同请求重放返回存下的原 ACK 的全部权威字段，只有传输元数据 replayed 从 false 改为 true，不再写／发事件／mint token，也不重新读取 snapshot。下文 exact ACK 均指这一规则；旧 ACK 不是最新 snapshot。noop 不造正文历史、不截 Redo。renderer 另守 mount/session/source/instance/edit-generation，失效 UI lease 只禁止旧焦点／导航回写，不抹掉已提交数据。

来源声明是编辑意图，不是客户端 target authority 或真实键盘事件的证明。带 bindingClaims 时，全部最终本地目的地须按实际完整 AST 恰好覆盖一次；continue 只能消费当前准确 BindingKey 一次，copy-current 可明确重复；copy-ticket 从 Main 已核验的冻结条目继承目标。继承要求实际解析 URL 与语法相同，改 href 必须声明 new；new 仍由 Main 按 immutable Origin 解析。客户端不提交 target。未携带声明的旧调用继续使用保守 fallback，遇到无法证明的多处编辑／split／join／copy 保稿拒绝。

内部 `getSyncedGroupSnapshotsWithLinkSources` 在同一独占只读世代验证真实 parser／ledger 后签来源票，只有整批校验及容量检查成功才发布内存句柄；不能为尚未提交的写事务状态签票。票绑定实际 DB connection、workspace scope 与 recovery epoch，保留冻结 target 与解析事实，源 revision、Redo 裁剪、改名、编辑器卸载不使其失效。来源 digest 仅覆盖来源身份、Origin 与核验 entries，不冒称完整 GroupWire hash。容量为 256 票／32 MiB 序列化条目，满时拒新票、不驱逐已有票；Main 重启或恢复世代变化后失效，未提交请求必须保稿拒绝，不按今日 URL 重新绑定。已提交请求仍先返回准确原 ACK，再考虑来源验证。此入口与句柄尚未接入生产 Store／IPC、PM／CM producer 或系统剪贴板；它不构成重启后内部粘贴保证。

renderer controller 的逐步声明相对于当前 working-before。合并同一事务帧时按精确中间 destination→source 组合，复制之复制展开到原 current／ticket 来源，未 ACK 的 new 仍是 new；不按相同 URL、文字或块顺序推 lineage。帧与本地 Undo／Redo 一起保留声明，串行保存后续帧使用前一准确 ACK 的正文键；same-text 的 new／copy 意图不能被正文相等判为 noop。真实编辑器 producer 与剪贴板 bytes／occurrence envelope 仍须后续接通和验证。

### 4. 结构恰有 command／host-final 两种互斥 authority

```ts
type Placement = { documentId: string; beforeBlockId: BlockId | null; parentBlockId: BlockId | null; depth: number }
type RootSelection = { documentId: string; selectedRootIds: BlockId[] } // 每根含完整子树，去重包含关系
type RefIdentity = { workspaceScope: Uuid; groupId: Uuid; creationId: Uuid }
type NewRefSource = { instanceId: Uuid } & (
  { kind: 'working'; sourceDocumentId: string; sourceInstanceId: Uuid } | { kind: 'internal'; identity: RefIdentity })
type StructureAction =
  | { kind: 'create'; documentId: string; selectedRootIds: BlockId[]; groupId: Uuid; instanceId: Uuid }
  | { kind: 'insert'; groupId: Uuid; instanceId: Uuid; target: Placement }
  | { kind: 'move' | 'duplicate'; selection: RootSelection; target: Placement }
  | { kind: 'move-batch'; moves: Array<{ selection: RootSelection; target: Placement }> }
  | { kind: 'delete'; selection: RootSelection }
  | { kind: 'paste'; fragment: StableBlockDraft[]; refSources: Array<{ fragmentBlockId: BlockId; identity: RefIdentity }>; replace: RootSelection | null; target: Placement }
  | { kind: 'detach'; instanceId: Uuid; groupId: Uuid }
type StructureApplied = {
  status: 'applied' | 'noop'; operationId: Uuid; historyToken: Uuid | null; replayed: boolean
  hosts: Array<{ documentId: string; logicalBefore: HostWorkingBefore['workingBefore']; logicalBeforeHash: string; after: DocumentDetail }>
  groups: GroupSnapshot[]; affectedInstanceIds: Uuid[]; blockIdMap: Array<{ from: BlockId; to: BlockId }>
}
type StructureBase = { clientOperationId: Uuid; hostsWorkingBefore: HostWorkingBefore[]
  groups: GroupGuard[]; expectedInstances: InstanceGuard[] }
applySyncedHostStructure(input: StructureBase & (
  { mode: 'command'; action: StructureAction } |
  { mode: 'host-final'; reason: 'source-apply' | 'selection-edit' | 'drop' | 'paste';
    finalAfter: Array<{ documentId: string; title: string; summary: string; blocks: StableBlockDraft[] }>; newRefSources: NewRefSource[] }
)): Promise<StructureApplied | Failure>
```

command：服务端读持久 P 核 CAS／owner，从动作前完整 working W 规划最终 A；create 子树取 W，保未 ACK 正文／新 ID／metadata，不从旧 P 或移除 children 后的 A 取。W 原始角色／身份／JSON／绑定严格，但允许待纠正 projection 超深；只验 A＋其它所有真实实例最终图。P→A 引用 diff须由command完整覆盖，W不能偷偷先删/移普通块；不预flush。create同时捕获reference/footnote闭包，额外复制定义分配fresh IDs，不能依赖原host留存。

delete/move/duplicate针对混合ordinary+refs完整根子树；跨页move复用既有planDocumentBlockTransfer及链接闭包规划，实例随其真实leaf维护registry；move-batch可一次浅移多个宿主且保W其它脏正文。同页移动去除选区后按稳定ID定位target，不能以数组offset猜。duplicate/paste为全部复制块fresh IDs并一次重写内部引用，ref仍同group；fragment局部ID仅供映射，refSources须匹配本workspaceScope及真实creationId＋当前GroupGuard。系统clipboard与SQLite非同事务：cut先成功写clipboard，再删根命令／host-final，拒绝时宿主不删。

host-final：W只作完整logicalBefore／owner来源，finalAfter与W宿主集合一一相等且为唯一写入authority；严格拒绝action/canonicalReplacement等额外键，不重放planner。Source完整Apply及Rich跨atom带marks的selection/cut/paste/drop由各自真实编辑核心生成A，Main不复制PM split。服务端严格校验A原始forest、P/W/A身份/元数据认领、exact refs与全部guards/投影；不允许canonical owner迁入迁出或创建组。既有instanceId不能手改groupId；新增ref须逐个fresh UUID并由newRefSources证明来自本W已核验ref的group/creation，或明确内部workspaceScope+group/creation身份；公开Markdown/HTML/fence不凭碰巧同ID绑定本机组。源码anchor只可取本W ID/metadata一次，外来metadata ID忽略；现source parser尾部clamp/reparent不能代替strict最终树验证。

两mode的每个实际ref增删/父级/深度/owner变化都须闭包guards，未声明或越域即拒绝。纯引用变更不消费/flush group working，dirty/conflict照保；detach只消费guard的准确已提交canonical，有未ACK working先解决版本，不偷偷物化旧内容。失败无部分落盘/历史，保草稿/Redo。DocumentDetail.blocks始终仅宿主叶引用；全局校验读全部真实实例。

### 5. 精确 history tail 与 inverse

```ts
restoreSyncedGroupOperation(input: GroupGuard & {
  clientOperationId: Uuid; expectedInstanceBinding: InstanceGuard
  historyToken: Uuid; expectedHistoryCursor: Uuid; direction: 'undo' | 'redo'
}): Promise<GroupSaved | Failure>
restoreSyncedHostOperation(input: {
  clientOperationId: Uuid; historyToken: Uuid; direction: 'undo' | 'redo'
  expectedHosts: Array<{ documentId: string; expectedUpdatedAt: string }>
  groups: GroupGuard[]; expectedInstances: InstanceGuard[]
}): Promise<StructureApplied | Failure>
getSyncedHostHistory({ documentId: string }): Promise<HistoryState>
```

- 每组只有一套共享内容 journal/cursor，多个实例共用 coordinator；组 Undo 必须命中当前允许的尾 token／cursor、精确语义 side 和当前 CAS。不能换成最新 expectedRevision 后越过另一实例的新写。Redo 只在该分支仍匹配时允许；sync／restore 外来替换建立不可跨越的新 history 边界，清除当前可执行分支，不仅重置 position 或更换 cursor，防止旧位置 1 重新成为 Redo。
- 成功 Undo/Redo 推进 cursor 并 mint fresh CAS；失败／noop 不移指针、不清 Redo。新成功内容编辑才截当前 Redo 分支。幂等旧 ACK 不再推进。宿主 Undo 永不重放 canonical snapshot。
- 结构 journal 存 logicalBefore=W、最终 A，P 只审计；一次结构 Undo 恢复 W，保原先脏文字。必须匹配参与 host 当前尾操作、CAS 和精确 after side；后续本地输入先按本地历史撤，不用旧 token 覆盖。
- 不转canonical owner的host操作（含insert/move/delete/duplicate/paste/host-final）之引用部分inverse只逆ref delta，允许组正文后来改变；请求带当前group/topology/binding guards，按当前canonical重验全实例最终图，不恢复旧组内容。普通正文仍按精确host side恢复；恢复实例fresh binding，ID/owner/深度不符拒绝。
- create/detach inverse 涉及 owner／内容消费，严格核对记录的准确组内容版本、owner 与使用者依赖；新增使用者或内容已变可拒绝，不能套纯引用宽限。所有 inverse 都验最终图；即使 logicalBefore 留存，非法旧投影也不能强写，token／Redo保留。

### 6. 首轮验收边界

唯一真实后台主窗，同页重复实例双向编辑、跨页实例、宿主/group dirty 分离、真实 CDP IME/迟到 ACK、独立 group Undo、columns/DB atom、保存重载；不得测试造第二 BrowserWindow 或放宽唯一 mainWindow IPC／插件生命周期来声称同 Store 双窗。

独立 repository/SQLite 客户端验证真实 CAS 一成一拒；两套独立 Store＋真实 HTTP WebDAV 验 wire/ETag/依赖/冲突收敛。两独立 App profile 只有实际同时启动并各获 profile 锁才可另称双应用 UI 同步；不等于同 SQLite 双主窗。非本机多窗口功能不纳本阶段。

wire仅语义group `{kind,id,creationId,createdAt,origin,bindings,blocks}`，不含本机CAS/history/opID；组createdAt独立持久且原样跨sync/V3，不从首child或token推导；manifest5精确instance→groupHash闭包。新group record≤5MiB，V3直接同closed JSON；protocol16MiB、每host重复展开10万节点/16MiB、V3总100MiB、单Markdown5MiB、模板1万节点/400万字符，不把新小门槛套旧无ref路径。V3整图映射/回滚/pins、旧25/4拒读、搜索/链接/附件/AI读canonical与内部引用/外部物化分离为门禁，原450KiB/96KiB入口预算不变。

正常关闭不得假称当前已有flush：唯一主窗 main prepare token/sender/window-generation 绑定，flush 或本机私有 recovery-journal durable receipt 后才允许 close/drain/shutdown；journal 不入 wire/V3，pending 只原 operation 查询、不盲重放。源码模态/IME 与 crash/OS kill 保证边界按 UI 短合同；不扩公开多主窗。

## 编辑器与正常退出

### 1. 身份、规范内容与来源
- 宿主只存 leaf `synced-block`，`block.id=instanceId`，严格 content=`{version:1,groupId}`；不保存 canonical 子块副本。
- group/instance 新 ID 为 UUID；旧 child ID 只验 string 且 trim 非空，保原字节，不加长度/字符集/id===trim 限制。
- canonical forest 非空，保稳定 child IDs、relative depth/parent/metadata；禁止任何 nested synced leaf（含隐藏后代）。
- 最后删除显式产生 fresh 稳定 ID 的真实空 paragraph，与删除同事务/同 history；Store 拒空，不自动补 filler。
- OriginV1 精确为 `{version:1,documentId,pathAtCreation,firstInstanceId}`，全 immutable；不用 linkContextPath。
- “Original”仅 firstInstanceId 对应实例；其删除后保逻辑 ID。已有链接绑定另存 authority，新相对链接按 pathAtCreation 解析。
- 每处透明展开 `instance.depth+canonical.maxRelativeDepth<=6`；后端在同事务验证全部实例最终图，不 clamp/flatten。
- 新组规范语义JSON自身≤5MiB；所有host实际重复展开共≤100000节点/16MiB等价wire，写前预检；旧无ref普通写不加小门槛。V3组文件用同closed GroupWire JSON，sourceRevision只在manifest；完整备份100MiB、plain单文件5MiB重导入与模板1万块/400万字符边界分别保留。

### 2. 单一 controller 与精确 scope
以下为 renderer 内存类型；复用 core 的 GroupSnapshot/GroupGuard/InstanceGuard/CanonicalEdit/StableBlockDraft，epoch/root 不进 IPC/wire。
```ts
type ForestOwner = {kind:'document';documentId:string}|{kind:'synced-group';groupId:string}
type ScopeBase = {
  hostDocumentId:string; windowSessionId:string; hostSession:object
  mountEpoch:object; bindingEpoch:object; domNamespace:string
  root:()=>HTMLElement|null; isCurrent:()=>boolean
}
type GroupScope = ScopeBase & {owner:{kind:'synced-group';groupId:string};instanceId:string;bindingVersion:string}
type ForestScope = GroupScope | (ScopeBase & {owner:{kind:'document';documentId:string};instanceId?:never;bindingVersion?:never})
type ScopeBookmark = {
  owner:ForestOwner; instanceId?:string; mountEpoch:object; bindingEpoch:object
  selection:EditorHistoryBookmark
}
type GroupDraftState = {
  snapshot:GroupSnapshot; working:CanonicalEdit[]; editSequence:number
  dirty:boolean; phase:'clean'|'dirty'|'saving'|'conflict'|'error'
}
type GroupController = {
  getSnapshot:()=>GroupDraftState; subscribe:(notify:()=>void)=>()=>void
  apply:(input:{scope:GroupScope;expectedEditSequence:number;guards:GroupGuard;
    blocks:CanonicalEdit[];bookmark:ScopeBookmark;transactionId:string})=>boolean
  checkpoint:()=>void; undo:(scope:GroupScope)=>Promise<boolean>; redo:(scope:GroupScope)=>Promise<boolean>
  flush:(options?:{shouldContinue?:()=>boolean})=>Promise<boolean>
}
```
- Source owner 管 workspace 级 groupId→controller，唯一 working/写队列/组 history；Rich 不复制 controller/autosave。
- 同组实例投影 working，实例自己的 selection/composition/fold/table/dialog/DB raw drafts 按 (instanceId,childId) 分离。
- DOM/React/session key 用 JSON tuple(domNamespace,ownerKind,ownerId,instanceId,childId,slot)，不冒号拼 opaque IDs。
- scope.hostDocumentId 始终真实宿主，只供导航/关系；owner 决定实际 persistence/history，禁止 fake DocumentDetail。
- 每 await 重验宿主/session/instance/binding/mount/expected content/getPos/attention；A→B→A 不复活旧回调。
- 内容 revision 与 topologyRevision 是本机 opaque UUID，只比较相等；不进 wire hash；typed event 不重置 host draft。
- apply 同步接受完整候选后 Rich 才 updateState；mirror external/addToHistory:false 不回调 apply、不建 history、不 focus。
- 已知预算拒绝非法结构且不建 checkpoint；外来变化使 working 冲突时保 draft/IME/selection/Redo，不盲换 CAS 重发。
- 最后 subscriber 只可回收 clean 且无 pending/composition/conflict 状态；dirty controller 保留至明确保存/恢复处理。

### 4. Host 结构：两个互斥 mode，各有唯一 final authority
IPC精确形状只引用core第4节applySyncedHostStructure输入（StructureBase＋互斥mode），UI不再定义另一份StructureRequest/HostWorkingBefore/RefProof。
- 两mode共同hostsWorkingBefore完整W；host-final另有finalAfter数组（宿主集合与W一一相等）及逐新实例newRefSources，字段/union直接用core，禁止另造hosts[{before,after}]/referenceProofs。
- command：P=持久CAS基线，W=动作前完整working，A=server.plan(W,typed action,guarded snapshots)；无finalAfter。create从W完整子树取未ACK内容，不从P或已删child的A取。
- host-final：W仅logicalBefore，finalAfter是唯一完整A；reason只诊断，server不再重放action，不接canonicalReplacement、不隐式建组或迁canonical owner，跨宿主保ID转owner用command。
- W严格验raw角色/父/ID/JSON，但可处于待纠正projection超深；只A与所有未参与对象当前持久状态组成的最终图要求全部合法。
- before覆盖全部参与宿主含目标页脏正文。command完整roots可含普通块/refs，move/cut/delete/duplicate一次规划；host-final覆盖Rich跨atom带marks文本的cut/paste/drop与Source完整Apply，不把PM splitter复制到Main。
- 两mode都核P→A全部ref diff/guards。existing instance不得手改groupId；newRefSources逐freshUUID按core working(sourceDocumentId/sourceInstanceId)或internal(identity)分支验证，外来Markdown/HTML与reason不授绑定权；command fragment/refSources/RootSelection也只取core shape。
- Source final由strict shared parse+anchors生成；anchors只取W中ID一次映射metadata，不带content/parent/depth authority；未知/外来ID fresh，未证明ref拒绝。禁止现source helper的clamp/reparent绕过严格最终校验。
- 原子写 host/group/identity/instances/routes/index/journal；响应返回服务端logicalBefore=W、完整A/新CAS/historyToken/opId。
- 两mode journal都是W→A，P仅审计/并发基线；不得普通半动作先改W再做ref半动作。一次Undo恢复W中早先未ACK编辑，不退回旧P、不reset旧普通history。
- group history独立：同组controller一条content链，已ACK Undo只消费可逆尾＋精确语义/CAS；失败保pointer/Redo，noop不截Redo。
- 纯ref inverse只逆ref delta，允许在当前content guards下跨内容revision但全实例深度重验；create/detach核验准确内容/owner/use集合。
- 成功Undo/Redo mint新本机CAS；同opId同hash重放仅返回原ACK，不重复写/事件，不改用新opId盲replay。
- 纯ref浅移/删除不flush dirty group、不提交或清除其working/history；dirty host直接W+move规划合法A，不先flush非法W。
- W如本来projection-invalid，Undo仍不得发布非法图：保token/Redo并报constraint；纠正入口不被导航flush/busy锁封死。
- IME中不启动结构命令/强制blur；短busy只覆盖参与host，ACK不覆盖迟到输入或恢复已失效selection。

### 5. closeRecovery：唯一真实主编辑窗
当前普通IPC只认 mainWindow 主frame；插件popup/私建BrowserWindow不是合法编辑peer，6c不增加多主窗registry。
```ts
type PrepareClose = {requestId:string;windowSessionId:string;workspaceRecoveryEpoch:string;reason:'window-close'|'app-quit'}
type RecoveryReceipt = {receiptId:string;requestId:string;closeGeneration:number;
  records:Array<{recordId:string;draftSessionId:string;generation:number;hash:string}>}
type CloseReply = {requestId:string;closeGeneration:number} & (
  {status:'flushed'}|{status:'draft-journaled';receiptId:string}|{status:'blocked';reason:string}
)
```
- IPC最小面：onPrepareClose(event)、writeSyncedRecoveryDrafts(token+closeGeneration+records)→RecoveryReceipt、replyClosePreparation(CloseReply)；恢复用list/read/discard(expectedGeneration/hash)，都复用可信主frame包装。
- main单协调器running→preparing→closing→draining→shutdown；close/before-quit先preventDefault，不先shutdown Store。
- prepare token绑定真实sender/mainFrame/windowSession/workspaceEpoch；renderer字符串不授信，旧token/receipt/generation拒绝。
- renderer冻结新增事务但不unmount；IME未自然结束则blocked，不伪造compositionend、不把候选当已提交正文。
- 尝试flush host/group；冲突/非法working不盲保存。其余完整draft+未Apply源码buffer写main私有侧库并等durable receipt。
- journal记录本机workspace/recoveryEpoch、draftSession/generation、groupId/creationId/base revision+hash、working/incoming、pending原opId/hash、关联W与可恢复selection；不序列化DOM/对象epoch。
- closeGeneration是整窗本次捕获世代，不是某组editSequence；receipt须覆盖全部余稿的准确draftSession/generation/hash。写失败/无响应/取消保窗/Store/草稿，旧ready失效，不timeout强退。
- 全flushed或余稿journal ACK后才allowClose→drain已接受写→shutdownServices→quit；重入只执行一次。
- 侧库建议 storage/recovery/synced-drafts.sqlite，排除canonical/V3/wire/主库安全副本；非未提交内容的第二authority。
- 重开先查当前源和original opId：已提交只确认submitted部分，后续working仍保；冲突显式处理，不自动重放或Apply源码。
- workspace恢复/替换换recoveryEpoch；旧草稿可显式查看，不自动套入新库；清理需expectedGeneration/hash。
- 此保证限正常close握手及已ACK落盘journal；崩溃/强杀/断电/未结束IME最后文字不得据此承诺。

### 6. 两层真实验收与冻结点
1. UI层：正常后台单主窗内两实例真实Source/Rich双向输入、IME/selection/DB/caption隔离、独立group/host历史；真实close/reopen＋侧库/Store断言，含conflict、非法W、pending ACK、源码buffer、journal失败。
2. 持久层：实际repository独立竞争CAS/owner/最终图/journal原子性；两独立SQLite+Service经真实HTTP测同步冲突/离线/重启/门禁与三轮备份。后者准确称独立持久客户端协议，不是双主窗/多机器多人。
- 双独立profile App可后续实际验收；不共DB、不绕单实例锁/IPC、不改插件单renderer生命周期；其结果不冒充同Store双窗CAS。

## 同步与完整备份

### 1. 公共语义与预算

- schema26／WebDAV protocol5／完整备份 V3 单向门禁；普通 Markdown、宿主内部源码、可信完整备份三种模式显式选择，不自动互猜。
- 沿用 core 的 `Uuid`、`BlockId`、`CanonicalWire`、`SyncedOriginV1`、`LinkBinding` 精确 closed runtime shape；未知字段、重复 JSON key、原型注入 key、非法 scalar 均拒绝，不作宽松 normalize。
- Origin 精确 `{version:1,documentId,pathAtCreation,firstInstanceId}`，全 immutable；bindings 是 group 同级可维护语义字段，source range 为 block.content 的 UTF-16 区间，raw 必须相符且目标经 main 核验。
- 新 group／instance／creationId 为 UUID。旧 child ID 只验 string 且 trim 非空，保原字节（包括首尾空白／中文／冒号），不新增长度／字符集限制；新 V3 codec 不借用会 trim ID 的旧分支。
- CanonicalWire 含必需有效 createdAt，继承旧 child 原值；不含 sortOrder、updatedAt 或本机信息。组非空、禁止全部 nested sync；最后删除显式 fresh paragraph 一事务，后端不补 filler。
- 每实例透明物化 `instance.depth + child.depth <= 6`；全局 ordinary／instance／canonical child 身份排他，parent、columns 权重／body、database-view 原子配置继续守现契约。
- 新组的**规范 portable GroupWire JSON ≤5MiB**，含 bindings／闭包／资产；protocol5和V3使用相同规范字节，不加wrapper。写前可用64个0 hash＋同编码name作无IO等长投影；共同visitor维护binding区间，真正portable/export仍验文件和实际bytes hash，不能用有IO的AttachmentStore.get/resolve冒充纯预算。
- protocol 单记录／manifest 仍 ≤16MiB，entries／实例依赖各最多100,000项；group 本身最多100,000块。每受影响宿主按实际 occurrence 重复展开计 ≤100,000块及 ≤16MiB 等价 document wire 体积，不只数 leaf／去重后 group。
- 等价 document wire 的计量口径固定为完整 host envelope 加逐 occurrence 的 canonical edit 行；去掉组 child.createdAt，保留每行旧 ID／parentBlockId 的原 UTF-8 字节并按透明深度计量。这不是可持久化的重复 ID forest，也不是分配 fresh UUID 后的公开导出大小；复制、翻译、模板或导出生成最终身份和文字后仍按各自实际输出及原上限检查，不能复用这个数字作输出体积证明。
- 新group／引用／移动／组编辑在写前验portable组及全部宿主投影；sync入站raw组／V3文件各量5MiB，出站转换为portable后再验；localize后SQLite/edit snapshot只复验shape／全图及已知portable预算，不因userdata长file: URL误拒。既有无ref普通保存路径不加小门槛。
- V3 继承单内容文件5MiB、JSON深度32、总内容100MiB及现文件数／目录／资产限制；JSON组文件纳同一总预算／文件数，不能绕 Markdown 扫描上限。超界在发布／恢复写前失败，旧归档限制不放宽。
- 普通物化输出的5MiB单文件／100MiB总量仅为现恢复器可重导入边界；多个各自合法组的宿主不保证普通输出≤5MiB。模板独立继承10,000块／4,000,000字符，按展开结果计，不能用 ref 压缩绕过。

### 2. Protocol5 closed shape

```ts
type Hash = string // 64位小写SHA-256；CanonicalWire／Origin／Binding采用core定义
type GroupWire = {
  kind:'synced-group'; id:Uuid; creationId:Uuid; createdAt:string
  origin:SyncedOriginV1; bindings:LinkBinding[]; blocks:CanonicalWire[]
}
type GroupDeletionWire = {
  kind:'synced-group-deleted'; id:Uuid; creationId:Uuid
  previousHash:Hash; deletedAt:string
}
type Manifest5 = {
  version:5; workspaceId:string
  entries:Record<`doc:${string}`|`group:${Uuid}`|'databases',Hash>
  syncedInstances:Array<{documentId:string;instanceId:Uuid;groupId:Uuid;groupHash:Hash}>
}
```

- 原 document／databases／deleted 记录字段与 key 语义保留；group 和其 tombstone 都用 `group:<id>`，不把旧 doc tombstone 猜成组删除。日期有效且保原字节，不作时钟胜负权威。
- GroupWire hash 仅规范语义 JSON；本机 revision／topology／binding UUID、clientOperationId、history／Undo、恢复草稿与 credentials 一律不入 wire/hash。接收不同语义 mint 本机新 CAS；noop 不 mint，不造成循环同步。
- creationId 是稳定逻辑创建来源，不是成员认证；同 groupId 不同 creationId 必冲突，不能按同名／同正文／路径合并。origin documentId／firstInstanceId 已删除仍保留逻辑身份。
- 宿主 leaf `type:'synced-block'`、`id=instanceId`、content严格 `{version:1,groupId}`；不含组正文、groupHash 或本机 revision。
- syncedInstances 按(documentId,instanceId)排序，精确等于全部 live host leaf；instanceId全局唯一，groupHash精确指 entries 对应 live GroupWire，不能指 tombstone。允许零实例 live group，不允许 missing group。
- 首次 feature、全部关联 host／group／依赖表与 version5 同一次 manifest ETag CAS；之后 sticky5，不因最后实例／组消失降级。group 改内容只改自身 hash 与依赖表，不 touch host.updatedAt／body hash。

### 3. 全候选图与冲突

- publish 前与 repository.apply 事务内共用纯最终图规划器：先 strict 校验所有已选 record、key/hash、完整依赖闭包和缓存命中，再做本机 catalog 映射及6b raw接收端catalogUUID拒绝；group 内 database-view 同等扫描。
- 最终图是实际拟发布的 writes＋incoming＋保留远端冲突版本＋未变记录；统一检验全局 owner、合法成对释放／接收、所有 host 的 live group、精确实例表、depth／展开预算、bindings／origin，不以单篇合法替代全图合法。
- doc→group 建组接收必须同时取得原 host 释放 child IDs 与 group 认领版本；统一 identity／routes 不删后重插，不能把现 doc-only `UPDATE blocks.document_id` 当跨域实现。
- 暂缓至少覆盖受影响 host↔group／身份转移依赖分量；异步下载期间参与版本变化，整分量 writes／incoming／accepted／依赖表一并撤回，不只撤单 doc 或组。无依赖分量可继续。
- 先校验／stage资产和hash对象；ETag发布前再核本机完整语义指纹；apply一SQLite事务重读、安装组／host／owner／实例／索引，最后写baseline及lastSyncAt。失败不推进参与基线；对象上传成为orphan不代表清单已发布。远端CAS已成功而本机apply失败时保留待收敛状态，下轮重读，不宣称HTTP与SQLite能跨系统回滚。
- 首版无public组物理删除API／UI、GC或出站group tombstone；最后实例删除保留orphan。入站tombstone仍核creationId／previousHash／全部live refs及trash/history/journal/template pins；不能以“当前页无实例”授权清理。
- 入站delete-vs-new-reference：远端删G、本机离线新增ref，两个顺序均以最终图产生依赖冲突，不能先删G或单发ref。保删除需明确计划处理相关ref及pins；保引用须已验证同creationId live内容恢复G，绝不补空组／丢无关正文。
- 三方合并只限同id／creationId、真实共同hash及相同stable-ID/type/顺序/父关系skeleton；抽现merge.ts纯helper逐块尝试，不伪造SyncDocument或套旧validId/validator。结构变化或binding区间无法唯一映射则显式整forest选择；保columns整组比例、DB原子content及现计算预算，绝不全文拼接。
- conflict decision绑定全部local／remote hash及依赖签名；拓扑变即失效，不能只看group hash。remote replacement 建新本机history边界，不把远端操作追加成本机可Undo旧journal。
- both 的原ID支固定远端；本机branch一次分配新groupId／creationId／全部child IDs，选中改指host用fresh instance IDs；doc双方副本也fresh doc／ordinary IDs。一次全图map父关系、payload、origin/bindings和内部links，同一G多处只fork一次。
- 预览明确哪些host改指fork；零实例fork须可读可管理。分配计划绑定hash并持久／稳定重试，不覆盖已编辑fork；未完成此完整规划前不开放group both，不借现docCopy冒充。

### 4. V3 exact 文件集与manifest

- Markdown文件保 envelope v1、`backupFormatVersion:'3'`、同一UUID `backupSnapshotId`；索引仍 `__knowbook/databases/index.md`，kind仍 `standalone-database-manifest`。识别完整归档后缺 marker／version／包一律拒绝，不降legacy。
- catalog路径仍`__knowbook/databases/catalog.md`、kind=`document-catalog-database`；custom仍`__knowbook/databases/database-<sha256(id)>.md`、kind=`standalone-database`。两者字段恰为kind/databaseId/databaseName/databaseDescription/createdAt/updatedAt/databaseColumns/databaseSavedViews/databaseEntities加V3/snapshot两项。
- doc仍无kind，字段恰为id/title/path/updatedAt/summary/documentDatabaseColumns/documentDatabaseFieldValues/documentDatabaseId加V3/snapshot两项；catalog是唯一columns authority。savedViews/config继续严格区分合法legacy缺省与非空损坏，不normalize损坏为显示全部。
- group文件仅 `__knowbook/synced/group-<sha256(groupId)>.json`，内容恰为规范 GroupWire，≤5MiB，无frontmatter／snapshot wrapper／sourceRevision。索引在同snapshot下精确认证路径、hash、creationId及全闭包，文件名不直接用opaque ID。
- index在V2的kind/backupFormatVersion/backupSnapshotId/catalogDatabaseId/databaseIds/documentIds/databaseMissingReferences/restoreDeletionPolicy之外，**必需且仅**增加下列三项JSON字符串字段；所有frontmatter值仍按现格式为JSON string scalar，嵌套JSON严格解析。

```ts
syncedGroups:Array<{id:Uuid;creationId:Uuid;sourceRevision:Uuid;recordHash:Hash}>
syncedInstances:Array<{
  id:Uuid;ownerDocumentId:string;groupId:Uuid;sourceGroupRevision:Uuid;sourceGroupHash:Hash
}>
syncedMissingReferences:{documentIds:string[];blockIds:BlockId[];instanceIds:Uuid[]}
// restoreDeletionPolicy保V2三项，仅再加：
syncedGroups:{mode:'source-owned-unreferenced'}
```

- sourceRevision仅archive一致性／provenance；每实例sourceGroupRevision/hash精确匹配组声明。V3组JSON直接保存protocol5同一portable GroupWire字节及hash，真实资产只用knowbook-asset://<lowercase sha256>/<canonical encodedName>，不改relative路径；普通MD资产保持既有relative表示。
- 文件集合恰为index＋catalog＋custom＋docs＋groups＋被引用资产；无混snapshot／漏包／额外定义。typed资产URI精确派生__knowbook/assets/attachments/<hash前2位>/<hash>/<name>，同hash不同name的别名文件不可省略；manifest认证组hash和资产闭包。零实例组仍有文件，缺group不可声明missing。
- syncedMissingReferences是扫描immutable Origin与typed binding targets得到的精确、去重排序missing集合，含已删firstInstanceId；已有live身份不得报missing。block／instance共用身份域，同一逻辑ID的多角色reservation一致。
- 共用严格资产parser/builder，拒credentials／port／query／fragment／编码别名，解析后重建须原字节相等。共同typed visitor只扫真实Markdown／有限格式资产字段；heading missing／unresolved-url语义保留，代码、DB配置/query/value、Origin普通字符串不扫描，不凭标题复活目标。
- portable转换同步维护bindings区间/raw再算hash，V3不二次改URL；复制时核安全路径、实际bytes hash及资产数量／体积预算，缺资产拒发布。恢复先验raw组5MiB/hash/闭包，再stage资产并localize及身份映射；随后只验本机shape／全图，不把变长file: URL套5MiB或沿旧hash冒充。
- inline data job、真实export worker、parse worker共用同codec／同闭包与预算，未知V3分支不normalize、不降V2；主库私有close-recovery侧库／op journal不入V3。

### 5. restore 单plan／fresh epoch／删除授权

- 原子read snapshot涵盖catalog/custom/列/view/entity/doc/group/child/instance/origin/bindings；group或拓扑独立变化须使backup revision变化，不借所有host MAX(updatedAt)。只导持久合法图，不把dirty草稿当authority。
- preview与apply同一可重验plan：预分配全部live及known-missing身份→统一改写父关系／payload／typed links／Origin→检验目标全图→stage可回滚资产→事务重验全部指纹→安装身份／内容／索引→授权prune→provenance提交。
- 同源恢复幂等依精确source lineage＋kind/source ID映射；group另核creationId，不按同名绑定。碰撞fork或显式拒绝；全局owner／retained身份也算占用。missing reservations指向未占用目标身份、无假live行，不能绑定目标碰巧同ID对象。
- Origin的不可变是同一逻辑对象不随路径移动／实例换宿主而变；可信全图迁移可依映射重写documentId／firstInstanceId，保pathAtCreation原字节，并对bindings已知目标同图映射，不改用新host context。
- 每次明确成功V3恢复均一次推进workspace recoveryEpoch；参与target group即使正文相同也fresh CAS/topology，实例fresh binding；sourceRevision不写回CAS。相同恢复请求已提交后的幂等ACK不重复mint，preview／取消／失败不推进；旧pending/Undo/close receipt失效，原draft仅显式恢复，不自动replay。
- DB、owner、routes、索引、history边界、provenance、baseline与资产发布失败整体回滚；不恢复源clientOperationId／credentials／Undo游标为可执行状态。preview变化必须重新规划，不静默改目标。
- 零doc归档documents.mode='none'，不删除真实docs；source-owned-unreferenced只限恢复plan精确来源集合且最终无host/trash/history/journal/template pins，不等于public组删除／后台GC。catalog映射不授权组删除，V2／legacy经instance生命周期仓库但无额外group prune权。

### 6. 建组定义闭包与两种Markdown模式

- create基于core的持久P核CAS、完整working-before W＋typed command规划A；从W整篇解析环境捕获selected subtree外的reference／named-footnote闭包，不孤立parse选中块、不先flush非法W／dirty group。

- 被选走definition若仍被host survivor使用，要复制其必要闭包回host；闭包中的链接按原拥有者target捕获后重建新block范围。现stage4不能安全定位的跨块／容器definition在任何写前拒绝，保草稿，不悄悄drop／flatten。

- 明确模式：public plain／外部clipboard每处可读独立物化，缺snapshot明确失败；internal host source保严格ref fence与out-of-band instance anchors，组source只编辑canonical。source fence只在受保护本机draft上下文识别，普通用户Markdown相同文本不自动加入本机组。
- 内部复制引用envelope须核同workspace／group creation与guards后fresh instance＋结构事务；外部导入独立内容。full source及混合选区走core互斥command／host-final，后者finalAfter是唯一目标、不重放action或迁canonical owner；普通update不得旁路，拒绝保buffer，不暗detach。
