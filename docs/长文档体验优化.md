# 复杂长文档的阅读与编辑体验

调研日期：2026-09-13。对比依据为产品官方帮助文档，未把第三方插件能力当作产品默认能力。

## 同类产品的做法

| 产品 | 官方提供的能力 | 对 KnowBook 的启发 |
| --- | --- | --- |
| [Notion](https://www.notion.com/en-gb/help/columns-headings-and-dividers) | 页面右侧目录随滚动保持可用；目录体现标题层级；支持折叠标题 | 长文档导航应始终可达，并避免占满正文顶部 |
| [Obsidian 大纲](https://obsidian.md/help/plugins/outline)与[阅读视图](https://obsidian.md/help/edit-and-read) | 大纲跳转、章节拖动；阅读视图隐藏 Markdown 语法，编辑视图保留修改能力 | 区分阅读定位与编辑焦点；阅读和编辑使用同一份内容 |
| [Obsidian 折叠](https://obsidian.md/help/folding) | 折叠标题和缩进列表，并提供全部折叠／展开命令 | 折叠不能让搜索结果无法到达，导航需要先展开目标祖先 |
| [Typora](https://support.typora.io/Focus-and-Typewriter-Mode/) | 专注模式淡化其他内容；打字机模式保持光标位置 | 先解决输入卡顿和滚动跳动，再考虑更强的专注模式 |

## 在代码与交互测试中发现的问题

1. 原大纲完整铺在正文开头，标题越多，正文越往下；滚动后缺少当前章节提示。点击大纲直接聚焦文本框，混淆阅读导航与编辑操作。
2. 原文内搜索通过 `filter` 后逐项 `indexOf` 取索引，命中多时产生重复遍历；摘要固定截取前 100 字，无法展示段落后部的命中内容；结果列表全部挂载。
3. `useDocumentsDomainState` 在每次 `draftBlocks` 更新后遍历所有文本框，交替写入高度和读取 `scrollHeight`。642 块样本的连续输入超时，调试暂停捕获到这段全量测量逻辑。
4. 行组件的内联 ref 在重新渲染时重复注册和测量，另有高度调整逻辑恢复了外层 `.content` 的滚动位置，而真正的滚动容器是 `.preview-panel`。
5. 编辑区域宽度变化缺少统一的重新测量入口，长段落换行后可能被裁切。

## 本次实现

- 常驻导航栏：大纲入口、当前章节、滚动进度、查找和阅读／编辑切换。大纲弹层可筛选，保留命中小节所属的一级标题；小窗口不强占一整列。
- 导航只滚动到内容，保留目录或搜索输入框的焦点；查找折叠列表中的内容时先展开祖先。当前章节随滚动更新。
- 阅读视图直接展示当前草稿，支持标题、强调、引用、列表、代码、公式、表格和已有媒体预览。隐藏正文编辑控件，禁用阅读时的全局撤销／重做；切换视图按内容块与相对偏移恢复位置。
- 搜索保留原始块索引，展示命中附近文字，同时最多渲染 60 条结果；支持 Enter、Shift+Enter、上下箭头与关闭快捷键。空结果和结果数变化不会访问无效索引。
- 移除每次输入都触发的全文文本框重测；稳定注册回调，仅对变化的文本框排队测量。首次显示和栏宽变化时将高度写入、读取分批处理，并恢复真实文档面板的滚动位置。
- 新样式随文档页面加载，保持首页资源预算。

## 验证范围

自动化样本包含 40 章、80 个标题、642 个内容块，覆盖中文长段落、代码、表格、嵌套与折叠列表。交互测试检查章节筛选、滚动位置、阅读切换、连续查找、折叠目标展开、连续输入、栏宽重排和草稿保存；搜索单元测试额外覆盖 2,000 块数据与段落末尾命中。

验证结果：类型检查与生产构建通过，首页资源预算检查通过；全量 649 项测试通过。31 项相关 Electron 交互用例完成验证，其中搜索焦点用例按新交互更新断言后单独重跑通过。Windows 进程查询用例在沙箱外的测试权限下复核通过，未修改该用例或对应生产代码。

## 后续边界

本次没有变更存储模型。标题仍沿用现有两级类型；没有加入标题章节折叠、章节拖动、跨重启阅读位置记忆或打字机模式。正文仍完整挂载，尚不能把这次验证推论为上万块文档也能流畅编辑。更大规模应先测量挂载、输入和保存耗时，再设计兼容跨块选区、拖动与焦点注册的虚拟化方案。
