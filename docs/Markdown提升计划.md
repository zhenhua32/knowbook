# Markdown 提升计划与验收记录

目标：继续完善 Markdown 支持，达到同类产品之上的水准。不能用增加少量语法或现有测试通过来代替完成这一目标。

## 对标依据（2026-09-18）

以官方文档公开的 Obsidian、Typora、Joplin 能力为参照。共同基线包括标准语法、表格与任务列表、脚注、数学公式、图表和文档链接；编辑器还需要便捷的表格操作、导航和格式操作。

- [Obsidian 基础语法](https://obsidian.md/help/syntax)、[高级语法](https://obsidian.md/help/advanced-syntax)
- [Typora Markdown 参考](https://support.typora.io/Markdown-Reference/)、[图表](https://support.typora.io/Draw-Diagrams-With-Markdown/)
- [Joplin Markdown 指南](https://joplinapp.org/help/apps/markdown/)
- [CommonMark 0.31.2](https://spec.commonmark.org/0.31.2/)、[GFM 规范](https://github.github.com/gfm/)

官方文档用于确定功能差距，不能证明 KnowBook 已经优于这些产品。最终需要可复现的同一组样本、操作步骤、往返差异和性能结果。

## 完成条件

- 每个阶段都有当前代码、自动化检查及真实运行的证据，没有以文档承诺替代实现。
- 官方用例全部纳入报告；失败和有意差异明确归类，不靠大量跳过获得“全通过”。
- 常用高级内容在编辑、阅读、粘贴、导入、导出与备份中保持一致；原始源码不会静默丢失。
- 表格、任务、公式、图表、脚注和链接的日常操作可直接完成，并验证撤销、保存与重载。
- 用相同样本衡量兼容性、往返保真度、编辑操作和长文档表现。只有证据支持时才宣称具体优势；未达成的差距保持公开。
